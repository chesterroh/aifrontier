## 编码智能体的10倍加速与研究品味瓶颈    *5:25*

<span class="paragraph-timestamp" data-ts="5:25">5:25</span> **金成铉** 我不太清楚其他开发领域的人对此有什么感受。但在我从事的领域，比如预训练领域，得益于编程智能体，工作速度确实大幅提高了。一个人能做的事更多了，能同时处理的任务也大幅增加，每项任务所需的时间也大大缩短了。

<span class="paragraph-timestamp" data-ts="5:51">5:51</span> **金成铉** 所以，开发 AI 的人是否因此觉得 RSI 之类的事更近了，我也说不准。也就是说，一个人能做的工作种类和所需时间，跟以前相比，过去必须亲自写的代码，现在几乎都不用自己写了。如今感觉限制我们的，是可用算力和手头想法的数量。

<span class="paragraph-timestamp" data-ts="6:12">6:12</span> **金成铉** 以前即使只有一个问题、一个想法，也得亲自把它写成代码。虽然实验本身由 GPU 来跑，但还得收集和分析结果。在这些工作中，除去运行实验所需的计算部分，其余部分所需的时间感觉都缩短到了接近零。认知负担也随之大幅降低。随着所需时间缩短到接近零，能同时进行的实验也大幅增加了。这么看，确实是大幅提速了。

<span class="paragraph-timestamp" data-ts="6:45">6:45</span> **金成铉** OpenAI 这周说，他们觉得自己的速度提高了约三倍。还有 Anthropic 等公司。他们觉得自己的速度提高了约十倍。我听到的说法大概是这样，而我个人觉得至少快了十倍，经常有这种感觉。那么，AI 本身的开发速度就已经大幅提高了。光这一点就很明显。

<span class="paragraph-timestamp" data-ts="7:08">7:08</span> **金成铉** 但说到 RSI，目前仍有人类的想法、研究偏好等因素在起作用，这些现在就是瓶颈。而这个瓶颈能否突破，我认为是决定 RSI 能否实现的最关键因素。

<span class="paragraph-timestamp" data-ts="7:23">7:23</span> **金成铉** 不过现在来看，Claude 也有自己的研究偏好。所以，即使我提出一个想法，如果这个想法有欠缺的地方，它也会自己补上。有时补得好，有时补得不好，感觉差不多各占一半。不过我还是觉得，很多时候它没补对，但有时也确实能补对。

## post-training一线的RSI质疑    *8:09*

<span class="paragraph-timestamp" data-ts="8:13">8:13</span> **张敏锡** 我觉得成铉刚才说的很有意思。我不做预训练，而是做 Gemini 的后训练。可以说，我们在模型接触用户之前，在最后阶段，从模型层面、权重层面完成能做的工作，模型再经过下一阶段，交到用户手里。从这个角度看，我基本都同意。生产力当然提高了很多，相比以前，能同时开展的实验类型、数量，以及实验的时长，确实都大幅增加了。但大家究竟在害怕 RSI 的什么，我还不太明白。

<span class="paragraph-timestamp" data-ts="8:50">8:50</span> **张敏锡** 无论是 RSI 还是 AGI 到来，大家是害怕工作会消失，还是觉得会出现什么别的问题？我会这么想。因为文本世界里可能发生的事，从 GPT-3 问世时起，我们不就认为已经定论了吗？此后，目标就只有那一个，我们似乎一直在努力朝它前进。把所有能用文本解决的问题都解决掉。如果一切都能转化为文本，或者转化为 token，投入算力之后，我们就能解决所有问题。现在展示的只是这条路线的延伸，我还不觉得出现了真正的新东西。

<span class="paragraph-timestamp" data-ts="9:34">9:34</span> **张敏锡** 比如最近的演示：给 Gemini 模型做机器人领域的少量后训练后，不管机器人是什么形态，它都能让各种机器人抓取物体。或者突然研发出新药之类的，目前还没展示出那样的成果。我们一直在既定的循环中运转，现在把它称为 RSI，我多少觉得有点像营销炒作。

## 探索已有知识与提出新问题的边界    *9:58*

<span class="paragraph-timestamp" data-ts="9:58">9:58</span> **朴钟贤** 关于这一点，我有个问题想请教。如果把 RSI 看作一种手段，它的潜力究竟体现在哪里？比如解决黎曼猜想，我们现在会把它转化为搜索问题，范围是人类迄今积累的全部知识，感觉仍是在这个范围内搜索。至于是否走出了这个范围，我还不确定。

<span class="paragraph-timestamp" data-ts="10:27">10:27</span> **朴钟贤** 新药研发之类的事也是如此。在已有知识的范围内，研发新药或许能找到一些插值点，但要走出去，提出新的理论呢？在这方面，如果 AI 能找到改进自身的方向，有没有可能走出已有知识的范围？我想听听大家的看法。

<span class="paragraph-timestamp" data-ts="10:46">10:46</span> **金成铉** 说到这里，我想到一件挺有意思的事。大概是两年前吧，Dwarkesh Patel在采访 Dario Amodei 时，Dwarkesh Patel曾问过这样一个问题。AI似乎掌握了人类的所有知识，为什么还不能把人类知识中分散的部分连接起来，创造出新知识呢？不过从某个时候开始，我觉得在数学领域似乎已经能做到了。

<span class="paragraph-timestamp" data-ts="11:06">11:06</span> **金成铉** 虽然我看不懂现在出现的那些数学证明，但大家都说，涉及的概念原本就已为人所知，只是以令人惊讶的方式把它们组合起来，用意想不到的方式将它们联系起来。我听到的都是类似的说法。这么想来，我觉得那个问题似乎在某个时候得到了解决。当然，这还是在同一个领域内。再进一步，还可以讨论能否把不同领域的概念也连接起来。不过那似乎是完全不同的问题。但至少在数学领域，似乎已经能结合已有知识，创造出新的东西了。

<span class="paragraph-timestamp" data-ts="11:42">11:42</span> **金成铉** 那么，从某种意义上说，这应该是通过scale-up和RL实现的。如果要讨论接下来的阶段，比如像Grothendieck那样，创造出全新的概念，或者建立新的公理体系，能否做到这些，似乎是数学领域如今提出的问题。而数学界似乎常说，因为目前还做不到这一点，所以这还不太有意思。光连接已有概念还不够，还得创造新概念，但他们似乎认为，目前还做不到。我觉得在机器学习领域，也会面临类似的问题。

<span class="paragraph-timestamp" data-ts="12:13">12:13</span> **金成铉** 把现有概念连接起来，改进算法，或者做优化，应该是可以的。那么，能否创造出全新的方法？我觉得这与刚才的问题也有些相通。不过能不能做到，我也不太确定。但如果真能做到，那在机器学习领域或许也能实现。

<span class="paragraph-timestamp" data-ts="12:33">12:33</span> **张敏锡** 我数学真的很差，也不太懂，不过有一点，比如说，某个猜想被证明了，那个猜想本来就是Riemann先提出的，AI只是非常擅长探索这个已确定的命题，尝试各种方法，最终把它证明出来，对吧？

<span class="paragraph-timestamp" data-ts="12:55">12:55</span> **张敏锡** 但这样的话，我觉得用RSI的概念来理解这件事，似乎不太合适。如果连Riemann可能提出的那类猜想也能找出来，并判断这些猜想是否合理，也就是说，能缩小搜索空间再推进，那我觉得，如果现在出现了完整的RSI，大概会是这样一种情况。

<span class="paragraph-timestamp" data-ts="13:14">13:14</span> **张敏锡** 不过，虽然那会是一项改变世界的技术，机器学习的公式毕竟很简单。所以从这个角度看，也许比较容易达到那一步。

<span class="paragraph-timestamp" data-ts="13:24">13:24</span> **李晋源** 我也常有类似的想法。如果问题已经给定，而解决问题的方法本身是以前没有的新方法，这种事是可以做到的。但目前要定义一个新问题，再逐步解决它，也就是说，重新定义问题这件事，我常觉得目前的能力还有些不足。

<span class="paragraph-timestamp" data-ts="13:44">13:44</span> **李晋源** 不过，至于这件事究竟能不能做到，我有两方面的想法。从可能做到的角度来说，我们还有很多方向没有探索过。比如把规模再扩大10倍、100倍，会不会真的出现涌现能力呢？而且是通过我们至今一直采用的方法。

<span class="paragraph-timestamp" data-ts="14:10">14:10</span> **李晋源** 另一方面，关于RSI，如果我们认为只要让它变得可验证，这个问题就能解决，那也得想想，现在的验证器是否设置得足够合理。我们目前采用的方式本身，是否构成了一个能够解决这个问题、设置完善的系统？我也有点觉得，关于这一点，或许未必是那样。

## Looped Transformer与CoT监控之争    *49:22*

<span class="paragraph-timestamp" data-ts="49:25">49:25</span> **崔胜准** 正好成铉来了，我还想问一件事：有人说不该用 Looped Transformer，但现在大家都在用吧？

<span class="paragraph-timestamp" data-ts="49:29">49:29</span> **金成铉** 好像也没人明确说不该用吧？

<span class="paragraph-timestamp" data-ts="49:35">49:35</span> **崔胜准** 没人这么说吗？METR 之类的机构，还有 Ryan Greenblatt 等人，不是说会看不到 CoT，所以应该少用一些吗？

<span class="paragraph-timestamp" data-ts="50:10">50:10</span> **金成铉** 对，我觉得大家都在用。它可能有不少优点。我研究的模型还没有涉及 Looped Transformer，但无论如何，参数数量减少本身对推理大概也有好处。在数据方面，它也可能有优势。

<span class="paragraph-timestamp" data-ts="50:26">50:26</span> **金成铉** 使用 Looped Transformer 的话，即使用相同的数据，在数据量受限时，也有可能达到更好的效果。我想大家大概也是看中了这一点。

<span class="paragraph-timestamp" data-ts="50:43">50:43</span> **金成铉** 不过，我确实会想，CoT 的可监测性真的有那么可靠吗？这确实帮了很大的忙，但能否百分之百依赖它，我觉得完全是另一回事。

<span class="paragraph-timestamp" data-ts="50:54">50:54</span> **金成铉** 这和是否使用 Looped Transformer 也是两回事。

<span class="paragraph-timestamp" data-ts="51:01">51:01</span> **李晋源** 从模型结构来看，在原有的非 LoopedTransformer 模型中，每采样一个输出 token，其他 token 的信息就会丢失，然后进入下一步。而如果不对 token 采样，直接把隐藏空间中的值传递给下一阶段，我认为这更有前景。

<span class="paragraph-timestamp" data-ts="51:25">51:25</span> **李晋源** 所以，虽说不输出 token，就进入下一阶段，会降低 CoT 监控能力，但就像成铉说的，它本来是否真的可靠，我也对此存疑。所以我个人认为，这是更好的方向。

<span class="paragraph-timestamp" data-ts="51:43">51:43</span> **金成铉** 目前常见的 Looped Transformer并不会直接传递 hidden state。它实际上仍然是 Transformer，和基本的自回归 Transformer 一样，输入的仍是离散 token，也就是文本 token，这一点也没变。

<span class="paragraph-timestamp" data-ts="51:57">51:57</span> **金成铉** 当然，也有直接传递 hidden state 的做法。所以我刚才想说的是，现在所谓的 LoopedTransformer 结构，除了共享参数这一点，并没有太大的不同，和基础模型相比也是如此。

<span class="paragraph-timestamp" data-ts="52:12">52:12</span> **李晋源** 我说的共享参数，是指如果把共享并重复的那部分边界看作模型原本的终点，那么传过去的就不是 token，而是让 hidden state 原样再循环一次。这样看，它其实是一个更小的模型，接着再循环一次，就相当于进入原本生成下一个 token 的过程起点。我觉得可以这样理解，所以才那么说。

<span class="paragraph-timestamp" data-ts="52:38">52:38</span> **金成铉** 对，那是 Looped Transformer，比如参数数量虽然相同，但对每个 token 循环计算，可能会增加计算量。

<span class="paragraph-timestamp" data-ts="52:50">52:50</span> **崔胜准** 我再问一个问题。如果用 Looped Transformer，让更小的模型发挥出更强的能力，那么在较小的规模下，就能多跑很多能观察到 scaling 特性的实验，会更有利吗？我是说从做实验的角度来看。

<span class="paragraph-timestamp" data-ts="53:05">53:05</span> **金成铉** 简单来说，可以认为每个参数所需的训练 token 数量是一定的。比如每个参数需要 20 个 token，可以这样理解。那么参数越多，所需的 token 也会越多。

<span class="paragraph-timestamp" data-ts="53:18">53:18</span> **金成铉** 举个例子，如果参数数量不变，同时又能提高模型性能，从这个意义上说，数据效率就可能提高。简单理解就是这样。实现这一点的方法之一，可以说就是 Looped Transformer。
