## 在旧金山举办的 Video as Code 主题活动    *00:26*

<span class="paragraph-timestamp" data-ts="00:26">00:26</span> **朴钟贤** 我在旧金山这段时间参加了相当多的活动，还围绕自己感兴趣的主题主办了一场活动。那场活动的报名者中，我们批准了大约100人参加，但场地没那么大，实际大约有40人到场讨论了这个主题。我们讨论的主题是 Video as Code。这个术语现在似乎还没统一。有人叫它 Code as Video，也有人叫它 Video as Code。总之，都是制作视频，但不用视频生成模型，比如很有名的 Seedance 这类模型，也不用直接生成像素的那类模型，而是让 LLM 编写动画代码，或者使用 Blender 等工具来制作视频。我们讨论了这种方法。对于这个主题，旧金山似乎也有很多人感兴趣。我们决定以此为主题办活动后，活动还登上了 Luma 活动平台的“Featured in San Francisco”栏目，也就是显示在旧金山的首页上。大概就是这个意思。大家对这个主题确实很感兴趣。


## 联合主持人 Sina 用代码制作的解说视频    *01:51*

<span class="paragraph-timestamp" data-ts="01:51">01:51</span> **朴钟贤** 这场活动不是我一个人办的，我和目前同住的一位土耳其创业者朋友一起主办了活动。这位朋友做得特别好，我想给大家看看他的作品，先来介绍一下。这是其中一个例子。这是用 AI 写代码，再由代码生成的视频。这位朋友本来就对教育很感兴趣，所以做的是讲解概念的视频。我们打开视频看看。像这样，概念的呈现方式，还有音频、音乐等，都是用代码生成的。这段讲的是神经网络，但不是讲如何用 RL 训练它。而是构建一个最基础的神经网络，讲它如何实现驾驶，又是如何运作的，是一段解释这种 AI 的视频。他做了这样的讲解视频，这条视频获得了75万次播放。后来他又围绕不同主题制作讲解视频，一条条上传，有的还获得了96万次播放。他现在总共才发了10条视频。他每天选一个想讲解的主题，做成视频上传。从这条讲解光线追踪的视频开始，播放量就涨起来了。连续上传了10天，有的视频还达到100万次播放，他就这样积累了不少关注者。


## 从 Manim 发展而来的 ManimGX 与教育梦想    *03:49*

<span class="paragraph-timestamp" data-ts="03:49">03:49</span> **朴钟贤** 这些就是和我一起主办活动的朋友 Sina 做的作品。他很早就开始做这件事了。听说大约是从18个月前开始的。

<span class="paragraph-timestamp" data-ts="04:00">04:00</span> **崔胜准** 18个月就算很久了啊。

<span class="paragraph-timestamp" data-ts="04:02">04:02</span> **朴钟贤** 按现在的标准，确实如此。从18个月前就开始了。3Blue1Brown频道的视频，大家可能都看过不少。Grant Sanderson 也为了制作那个频道的视频，开发了 Manim 这个库，再用这个 Python 库制作图形来讲解，对吧？为了把这件事做得更好，又自己开发了升级版 ManimGX，并用它亲手制作视频，做出了这样的作品。我问过为什么要做这些，因为理解复杂概念对每个人来说都不容易，如果能把概念清楚地呈现出来，让人更容易理解，大家就能更好地理解概念，也会喜欢上学习，教育也会随之进步。就是抱着这样的想法在创作。

<span class="paragraph-timestamp" data-ts="04:53">04:53</span> **崔胜准** 我看 3Blue1Brown 的视频时，总是很惊叹，看时也觉得自己好像懂了，但事后常常觉得其实没弄明白。

<span class="paragraph-timestamp" data-ts="05:05">05:05</span> **朴钟贤** 我们也聊到了这一点。我也问了他对此怎么看。真正让人理解，当然是最终目标。在他看来，3Blue1Brown 在这方面已经尽最大努力让观众真正理解。不过，教育类内容在 YouTube 等平台上实在太多了。大多数视频其实以播放量为目标，看时觉得自己懂了，实际上却没有深入理解。他说，这种浮于表面的视频很多。这也因为深入讲解的视频很难制作，所以难免会出现这样的内容。所以 AI 如果能在这方面帮上忙，就能帮助人们以更简单、直观的方式理解那些真正复杂的概念。他是这样解释的。

<span class="paragraph-timestamp" data-ts="05:55">05:55</span> **崔胜准** 这确实有潜力，但就像看网课一样，看过视频和真正把知识学进脑子里，似乎还是有点差距。

<span class="paragraph-timestamp" data-ts="06:05">06:05</span> **朴钟贤** 对，这话也有道理。我也是，真有需要时会努力弄懂，反复看上两三遍；但如果只是随便看看，就很难一遍完全看懂。不过，它确实有帮助。


## 从原始影像素材出发的 Kurzgesagt 风格实验    *06:21*

<span class="paragraph-timestamp" data-ts="06:21">06:21</span> **朴钟贤** 因为我也在做类似的事，当时Sina 做了一场分享，我也做了一场分享。我是从视频剪辑开始着手的。刚才展示的例子，真的是从零开始做的。那是从无到有制作的视频，而我关注的是原始视频素材，比如我们现在正在录制的这种原始素材，怎样才能用它做出更好的视频？我是从这个问题开始的，也尝试过类似的生成方式，现在也给大家看个例子。关于计算机运算原理的视频，我们的一位联合创始人尝试制作过。用的是一种很有名的风格，就是 Kurzgesagt 的风格。我把这些视频都看了一遍，觉得做得相当不错。所以，这样的视频是怎么做出来的？我想聊聊这个。


## 兼职 YouTuber 的剪辑负担与 AI 完成 99% 剪辑的频道    *07:41*

<span class="paragraph-timestamp" data-ts="07:41">07:41</span> **朴钟贤** 首先，我想从自己为什么开始做这些事说起。大家也看到了，我们是 YouTuber。这个频道也是我和别人一起主持的，我还主持 sudoremove 频道。其实我之前没说过，我还有一个运营得更久的频道，比这两个频道都早。我经营着这些频道，但这都不是我的本职工作，而是副业。我们也是抽出周末时间来拍摄的。就拿我的频道来说，一开始所有剪辑都是我自己做的，剪辑比想象中耗时得多。录下来的视频并不那么完美。我们的sudoremove频道也会做直播，直播视频也不可能尽善尽美。所以经过剪辑，当然能做出更好的内容。可以把内容讲得更清楚，弥补失误，还可以加入补充说明的视频，也可以加入补充资料。但每期至少要花20小时。自己做过就知道了。当然，每个人花的时间可能不同。所以这个项目最初的出发点是：AI能不能替我剪辑？我们就是带着这个想法开始的。我们为此做了几个月，现在sudoremove频道的视频都是由AI剪辑后上传的。开始这样上传视频到现在已经两三个月了。

<span class="paragraph-timestamp" data-ts="09:17">09:17</span> 一开始，人工和AI剪辑的视频各占一半，播放量也差不多。我还问了几位认识的订阅者，他们说：“没想到是AI剪的，质量挺好。”很多人都这么说，所以现在上传的视频有99%是AI剪辑的。后来，播放量也增加了不少。并不是因为用了AI剪辑，单条视频的播放量就更高了。而是因为用了AI剪辑，我们能上传更多视频，总播放量也就增加了。总之，我们觉得效果和以前差不多，和人工剪辑的视频差不多。

<span class="paragraph-timestamp" data-ts="09:51">09:51</span> **崔胜准** 红色箭头标的就是那个时间点吧。

<span class="paragraph-timestamp" data-ts="09:54">09:54</span> **朴钟贤** 对，我们差不多从那时开始用的。一开始是试着用。


## 用运动员网红的粉丝频道比较 AI 剪辑效果    *10:02*

<span class="paragraph-timestamp" data-ts="10:02">10:02</span> **朴钟贤** 后来，我们又做了些实验：和人工剪辑师相比，AI能做得更好吗？能不能做出让观众满意的视频？于是，我们在一位我认识的博主的频道上做了实验。他的频道大约有一万名订阅者，他也会做直播。他也会上传直播剪辑版。我们征得同意后，提出用他的直播素材剪视频，试着运营一个粉丝频道。我们说，这样能让内容传播得更广。得到许可后，就上传了AI剪辑的视频。结果播放量反而更高。

<span class="paragraph-timestamp" data-ts="10:43">10:43</span> **崔胜准** 是吗？

<span class="paragraph-timestamp" data-ts="10:44">10:44</span> **朴钟贤** 对，其实原因很清楚。因为他原本就不是做视频的。我们当然也不是做视频出身，所以在我们的频道里，我剪的视频和专业制作人做的视频相比，剪辑技术当然差得远。他也有自己的本职工作，其实是一名运动员。作为副业，他会剪辑并上传这类视频。毕竟他不是专业制作人，这也很正常。总之，我们开了一个新频道，上传AI剪辑的视频，即使当时订阅者为零，播放量还是更高。由此看来，AI在剪辑方面确实似乎已经比非专业剪辑者做得好。

<span class="paragraph-timestamp" data-ts="11:29">11:29</span> **崔胜准** 虽然还谈不上出类拔萃，但也许能达到平均水平，甚至超过平均水平。

<span class="paragraph-timestamp" data-ts="11:36">11:36</span> **朴钟贤** 后来，他说视频做得很好，请我们上传到他的主频道，所以现在我们也在那边上传。结果播放量明显提升了。当然，目前样本还不够多，不能断定播放量大幅提升就是因为剪辑做得好。但无论如何，我们已经看到了这样的积极结果。AI在剪辑领域也做得相当不错了。可以这么理解。


## SudoCut 发布：短视频剪辑与英语自动配音    *12:11*

<span class="paragraph-timestamp" data-ts="12:11">12:11</span> **朴钟贤** 所以我开发了一个叫 SudoCut 的服务，上线并开放给大家使用。那么，剪辑之后该做什么呢？接下来我开始做的是切片。也就是制作短视频。说到切片，最近我把我们做的一场直播那场直播大约有两三个小时。剪辑后，这段一两个小时的直播视频就成了长视频剪辑版。再从中挑出精彩片段，把观众可能喜欢的部分剪出来，做成短视频。因为现在这类内容很受大家欢迎，尤其是短片段。总之，我们也会把精彩瞬间一个个剪出来上传。一开始是怎么做的呢？只是把合适的片段挑出来。不加任何修饰。讲的是大家可能感兴趣的内容，接着就开始尝试制作动态图形。从这里开始，就进入了今天的主题 Video as Code，也就是让 LLM 生成制作动态图形所需的代码，再制作符合这些短视频片段内容的动态图形。顺便说一句，这段内容还配了英语版，来听听。

<span class="paragraph-timestamp" data-ts="13:53">13:53</span> **崔胜准** 感觉和钟贤的声音差别挺大。

<span class="paragraph-timestamp" data-ts="13:55">13:55</span> **朴钟贤** 那个声音是因为我们原本用韩语直播，后来自动配成了英语，所以听起来不太搭。不过也可以做韩语版本。用原来的声音。总之，就是这样根据内容制作相配的动态图形。我从大约两周前开始尝试这件事。


## Opus 5.5 点燃 Video as Code 热潮与工具比较    *14:16*

<span class="paragraph-timestamp" data-ts="14:16">14:16</span> **朴钟贤** 真正促使我开始尝试的契机是Opus 5.5。大家都知道它做得非常好。

<span class="paragraph-timestamp" data-ts="14:25">14:25</span> **崔胜准** 没错。

<span class="paragraph-timestamp" data-ts="14:25">14:25</span> **朴钟贤** 所以，Video as Code或者 Code as Video，这个概念从 Opus 5.5 开始浮现在我脑海里，于是我就测试了一下。Opus 5.5 的 medium、xhigh，还有 GPT-6.1 Sol、GPT-6 Astra，我比较了它们制作的动态图形。给它们的指令都一样。生成的动态图形大概是这样，Opus 5.5 真的做得很好。不过 GPT-6 也做得很好。也就是说，现在的模型做这些都还不错。得出这个结论后，我又做了一个实验。归根结底，我们得给 LLM 提供工具，对吧？所以我试着给它提供了几种工具。ManimGX，是刚才提到的曾和我们一起生活的朋友 Sina 开发的，是一个升级版的 Manim 库。它与 Manim 完全兼容，所以可以看作是给了模型 Manim。给它 Manim，让它用 Python 制作动态图形。再试试什么工具都不给，让它自己想办法。另外，现在还有不少这类项目已经发布在 GitHub 上。比如 Remotion 和 HyperFrames，这些都是用来制作这类图形的库。我把这些工具逐个提供给模型，让它分别用这些工具制作。最后生成的视频呈现出各不相同的图形效果，确实有些差别。

<span class="paragraph-timestamp" data-ts="16:09">16:09</span> 但要说哪个真的更好，就很难选了。我发现自己不太擅长从中筛选。不过关键在于，无论给它什么工具，它都做得不错。甚至不给它任何工具，让它直接写动态图形代码，画出来的效果也不差。于是我得出了这样的结论。

## 把声音重新误读为图像和表情符号    *32:03*

<span class="paragraph-timestamp" data-ts="32:03">32:03</span> **崔胜准** 接下来，我试着把刚才的 3 号当作图像来看。我们听一下。这样就会出现奇妙的图像，原本的代码被转换成声音，现在又被转换成了图像。不过编程久了就会发现，名称是可以随意取的。符号学里也是这样，就像能指和所指，我被称为崔胜准，并不是因为这个名字代表我的原子结构，这种关系是任意的。对，变量也是如此。所以，能够处理名称在编程中非常重要。给事物命名后，就能像魔法师一样操控它。有位作家叫 Ursula Le Guin，写过一部很棒的奇幻小说《地海传奇》，书里也讲到，知道名字就能干预，就能发号施令。所以，知道名字后，其实就能通过代码操纵某些东西。而这又能实际作用于物理世界中的光或马达之类的东西，所以在我心里，它是一种能干预现象的语言。我做的，就是尝试用原本未曾设想的方式去解读它。刚才展示的那些内容，我来播放一小段。现在这里显示的部分被解读成了一只熊。这是通过回归分析，找出了像素与这部分相似的表情符号。其实两者毫无关联，就像我们看云时，会从云里看出人脸一样。有个概念叫“空想性错视”（pareidolia），我就是用这种方式让它强行解读。

<span class="paragraph-timestamp" data-ts="34:09">34:09</span> 可一旦这样强行解读，它就有了“熊”的含义，这里也有了“流星”的含义。这里呈现的，是把这个结构表示成一种数学上的结，然后生成了它的轨迹。这也是任意的。所以我想探索的是，能怎样解读它。

<span class="paragraph-timestamp" data-ts="34:38">34:38</span> **朴钟贤** 总之，先用代码设计声音，再把生成的声音呈现为图像，然后把图像与相似的东西匹配，做成表情符号，就像给它起别名一样，最后表情符号就成了别名。
